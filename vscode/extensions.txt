# ==============================================================================
# extensions.txt — extensions both editors get
# ==============================================================================
#
# WHAT: Extension ids, one per line, installed into BOTH Visual Studio Code and
#       Cursor by install.sh. Blank lines and lines starting with # are ignored.
#
# WHY : Neither editor has a declarative equivalent of Zed's
#       auto_install_extensions — nothing in settings.json can install an
#       extension, and .vscode/extensions.json is workspace-level
#       *recommendations* only. So the list lives here and install.sh feeds it
#       to each editor's CLI, which is the shipped mechanism rather than a
#       third-party manager.
#
# HOW : The installer runs `code --install-extension <id> --force`, and the
#       same for `cursor`. The --force flag makes it idempotent and upgrades in
#       place. Regenerate a starting point with `code --list-extensions`.
#
# THE REGISTRY SPLIT — why there are three lists
#       The editors resolve ids against DIFFERENT galleries. Visual Studio Code
#       uses Microsoft's Marketplace. Cursor uses its OWN gallery at
#       marketplace.cursorapi.com (declared in Cursor.app's product.json), which
#       mirrors a large slice of the Marketplace — which is why ms-python.python
#       and ms-vscode.cmake-tools appear below rather than in the VS Code-only
#       list. What it does NOT carry is Microsoft's licence-restricted
#       extensions: Pylance, the C++ tools, and the ms-vscode-remote.* family.
#       Anysphere publishes forks of those, listed in
#       ../cursor/extensions-cursor.txt.
#
#       Do not guess which gallery has what — ask it:
#         curl -s -X POST \
#           https://marketplace.cursorapi.com/_apis/public/gallery/extensionquery \
#           -H 'Content-Type: application/json' \
#           -H 'Accept: application/json;api-version=7.2-preview.1' \
#           -d '{"filters":[{"criteria":[{"filterType":7,
#                "value":"<publisher.name>"}]}],"flags":914}'
#       An id that comes back empty belongs in extensions-vscode.txt instead.
#
# DELIBERATELY ABSENT: vscodevim.vim. These editors are configured as normal,
#       non-modal editors, exactly as Zed is — Neovim is where modal editing
#       lives. This note exists so the omission reads as a decision rather than
#       an oversight.
# ==============================================================================
